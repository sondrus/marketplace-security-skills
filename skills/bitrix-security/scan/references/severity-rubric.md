# Severity Rubric for Bitrix PHP Modules

Единственный источник истины для назначения severity. Назначай ровно один из трёх уровней — `high`, `medium`, `low` — по принципу ниже. При расхождении с точечными подсказками в `vulnerability-checklist.md` (в частности, reflected XSS и Open Redirect) — следуй этой рубрике.

> Этот файл задуман как easily-editable: правь списки ниже, чтобы менять калибровку. SKILL.md и vulnerability-checklist.md ссылаются сюда и не дублируют содержимое.

## HIGH — блокирующий
- неаутентифицированный RCE / Command Injection (eval, system, exec, proc_open, shell_exec, passthru, backtick, addAgent);
- неаутентифицированный Path Traversal / LFI / RFI;
- PHP Object Injection — подтверждённый unserialize без проверки CheckSerializedData / опции allowed_classes;
- неаутентифицированная загрузка произвольных/исполняемых файлов в web-доступную область;
- неаутентифицированный SSRF с доступом к internal-сети и возвратом ответа атакующему или цепочкой к RCE;
- неаутентифицированный XXE — обработка XML с включённой опцией LIBXML_NOENT;
- логирование чувствительных данных в document_root по предсказуемому пути;
- захардкоженные секреты, общие для всех инсталляций модуля (ключи платёжных систем, приватные ключи, мастер-пароли);
- IDOR / mass assignment без проверки владельца, выполняющий привилегированное или денежное действие, доступный анониму или пользователю сайта;
- бизнес-логика с прямым финансовым ущербом без авторизации — манипуляция ценой/количеством/скидкой в корзине, обход купонов, начисление бонусов (sink'и Sale\Order, CSaleBasket, обработчики OnSalePayment/OnSaleOrderSaved);
- подтверждённый бэкдор: обфускация (`eval(gzuncompress(base64_decode(...)))` и подобное) в сочетании с exec-/сетевым-/файловым sink или эксфильтрацией. Обфускация сама по себе (минификация, упакованные вендорные библиотеки, base64-ресурсы) — не находка.

## MEDIUM — существенный, не блокирующий
- SQL-инъекция;
- межпривилегиальный stored XSS — данные, внедряемые менее привилегированным атакующим (аноним, клиент, оператор), исполняются в интерфейсе администратора (списки заказов, очереди модерации);
- CSRF на значимое state-changing действие;
- reflected XSS.

А также находки, требующие аутентификации (оператор модуля или администратор) либо специфических условий, которые атакующий не контролирует напрямую:
- эскалация привилегий внутри аутентифицированной зоны (оператор получает действия полного администратора);
- SSRF ограниченного воздействия — исходящие запросы без возврата ответа (blind, egress-only);
- authenticated IDOR, Open Redirect при наличии сессии;
- слабая криптография для security-токенов (mt_rand/rand для сброса пароля и токенов, md5/sha1 без соли для паролей);
- race condition / TOCTOU в чувствительной операции (повторное применение купона, двойное начисление бонуса), если требует аутентификации.

## LOW — hardening / информационный
- Information Disclosure без пользовательских/платёжных данных (версии, пути, debug-вывод);
- CSRF в незначительном действии;
- мёртвый/недостижимый код с опасным паттерном;
- self-XSS (контекст виден только самому пользователю);
- слабая криптография в некритичном для безопасности контексте;
- Open redirect; использование функции `LocalRedirect` — не баг.

`riskLevel` = максимальная severity среди всех находок. `none` если уязвимостей нет.
